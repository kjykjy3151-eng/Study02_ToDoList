# 1부. 제품 요구사항 (PRD)

## 1. 배경과 목적

매일 10~20개의 할 일을 업무·개인·공부로 나눠 관리하고, 얼마나 해냈는지 한눈에 보고 싶다. 기존 앱은 기능이 많고 계정 가입이 필요해 부담스럽다. 설치나 서버 없이 브라우저에서 파일을 열면 바로 쓸 수 있는 가벼운 앱을 만든다.

### 목표
- 할 일 하나를 5초 안에 추가한다 (입력 → Enter).
- 전체·카테고리별 진행률을 화면 상단에서 바로 확인한다.
- 새로고침하거나 브라우저를 닫았다 열어도 데이터가 유지된다.
- 프레임워크·빌드 도구 없이 HTML, CSS, 순수 JavaScript만 사용한다.

### 비목표 (이번 버전에서 하지 않음)
- 회원가입, 로그인, 여러 기기 간 동기화
- 날짜별 목록 관리, 마감일, 알림, 반복 일정
- 하위 할 일, 태그, 우선순위
- 사용자 정의 카테고리 (업무/개인/공부 3개 고정)
- 순서 직접 변경 (드래그, 위/아래 버튼)
- 데이터 내보내기/가져오기 (백업)
- 삭제 실행 취소, 완료 축하 메시지

## 2. 확정된 제품 결정

| 주제 | 결정 | 이유 |
|---|---|---|
| 날짜 처리 | 날짜 구분 없이 **하나의 누적 목록** | 구조가 가장 단순함 |
| 완료 항목 정리 | **"완료 항목 지우기" 버튼**으로 직접 일괄 삭제 | 진행률을 "이번 할 일 묶음" 기준으로 리셋할 수 있음 |
| 정렬 | **자동 정렬**: 미완료가 위, 완료가 아래. 각 그룹 안에서는 최근 추가순 | 10~20개 규모에서는 필터로 충분함 |
| 백업 | **없음** | 매일 바뀌는 목록이라 잃어도 피해가 작음 |
| 진행률 의미 | 현재 목록에 있는 할 일 중 완료한 비율 | 누적 목록 방식에 맞춤 |

## 3. 사용자 시나리오

1. 아침에 앱을 열고 카테고리를 골라 오늘 할 일을 연달아 입력한다.
2. 일을 끝낼 때마다 체크하고, 상단 진행률이 올라가는 것을 본다.
3. 업무 시간에는 "업무" 필터만 켜서 업무 목록에 집중한다.
4. 오타를 낸 할 일은 더블클릭해 바로 고친다.
5. 한 묶음을 마치면 "완료 항목 지우기"로 정리하고, 진행률을 새로 시작한다.
6. 다음 날 브라우저를 다시 열어도 남은 할 일이 그대로 있다.

## 4. 기능 요구사항

### 4.1 할 일 추가
- 카테고리(업무/개인/공부)를 고르고 내용을 입력한 뒤 Enter를 누르거나 [추가]를 누르면 등록된다.
- 카테고리 기본값은 마지막으로 고른 카테고리다.
- 앞뒤 공백을 제거한 내용이 비어 있으면 추가하지 않는다.
- 내용은 최대 200자다.
- 추가하면 입력창이 비워지고 커서가 입력창에 남아 있어 바로 다음 할 일을 쓸 수 있다.

### 4.2 할 일 수정
- 할 일 글자를 더블클릭하거나 [수정]을 누르면 그 자리에서 입력창으로 바뀐다.
- Enter를 누르거나 다른 곳을 클릭하면 저장되고, Esc를 누르면 취소된다.
- 내용을 다 지우고 저장하면 원래 내용으로 돌아간다.
- 수정할 때는 글자만 바꾼다. 카테고리를 바꾸려면 삭제하고 다시 추가한다.

### 4.3 할 일 삭제
- [삭제]를 누르면 확인 없이 바로 지워진다.
- "완료 항목 지우기" 버튼은 완료 항목이 있을 때만 보이고, 버튼에 개수가 함께 표시된다. 누르면 확인 창을 거쳐 완료 항목을 모두 삭제한다.

### 4.4 완료 체크
- 체크박스로 완료/미완료를 전환한다.
- 완료 항목은 취소선과 흐린 색으로 표시되고 목록 아래쪽으로 내려간다.

### 4.5 카테고리 분류
- 카테고리는 업무, 개인, 공부 3개로 고정한다.
- 각 할 일에 카테고리 배지를 색과 글자로 함께 표시한다 (업무 파랑, 개인 초록, 공부 보라).
- 필터(전체/업무/개인/공부)로 목록을 거른다. 고른 필터는 새로고침해도 유지된다.

### 4.6 진행률 보기
- 전체 진행률을 `완료 수 / 전체 수 · 퍼센트`와 막대로 표시한다.
- 카테고리별 진행률(업무·개인·공부)을 각각 완료 수/전체 수와 막대로 표시한다.
- 진행률은 필터와 상관없이 항상 전체 목록 기준이다.
- 할 일이 0개면 `0 / 0 · 0%`로 표시한다. 퍼센트는 반올림한다 (예: 12개 중 7개 → 58%).
- 추가·수정·삭제·체크를 하면 즉시 갱신된다.

### 4.7 데이터 유지
- 변경할 때마다 즉시 브라우저 저장소(localStorage)에 저장하고, 페이지를 열 때 불러온다.
- 저장된 데이터가 손상됐거나 저장소를 쓸 수 없어도 앱은 동작하고, 상황을 안내한다 (자세한 내용은 2부 9절).

### 4.8 빈 화면 안내
- 할 일이 하나도 없으면 "할 일을 추가해 보세요"를 보여 준다.
- 필터 결과가 없으면 "이 카테고리에 할 일이 없습니다"를 보여 준다.

## 5. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 실행 | `index.html`을 더블클릭해 열면(`file://`) 서버나 빌드 없이 실행된다 |
| 기술 | HTML5, CSS3, 순수 JavaScript. 외부 라이브러리·프레임워크를 쓰지 않는다 |
| 브라우저 | 최신 Chrome, Edge, Safari, Firefox |
| 성능 | 할 일 100개에서도 조작 후 화면 갱신이 100ms 안에 끝난다 |
| 반응형 | 360px 폭 휴대폰부터 데스크톱까지 가로 스크롤 없이 쓸 수 있다 |
| 접근성 | 키보드만으로 모든 기능을 쓸 수 있다. 체크박스·버튼에 레이블을 붙인다. 색만으로 정보를 구분하지 않는다 |
| 보안 | 사용자 입력은 `textContent`로만 화면에 넣어, 입력한 코드가 실행되지 않게 한다(XSS 방지) |

## 6. 수용 기준

- [ ] 카테고리를 고르고 내용을 입력한 뒤 Enter를 누르면 미완료 항목 맨 위에 추가된다.
- [ ] 빈 문자열이나 공백만 입력하면 추가되지 않는다.
- [ ] 더블클릭으로 수정하고 Enter를 누르면 반영되고, Esc를 누르면 취소된다. 내용을 다 지우고 저장하면 원래 내용이 유지된다.
- [ ] [삭제]를 누르면 항목이 사라지고 진행률이 갱신된다.
- [ ] 체크하면 취소선이 그어지고 완료 그룹으로 내려간다.
- [ ] "완료 항목 지우기"는 완료 항목이 있을 때만 보이고, 확인하면 완료 항목만 삭제된다.
- [ ] 카테고리 필터를 고르면 해당 카테고리 항목만 보이고, 진행률은 바뀌지 않는다.
- [ ] 진행률이 전체·카테고리별로 정확하다 (12개 중 7개 완료 → 58%). 0개일 때 오류 없이 0%다.
- [ ] 새로고침 후에도 할 일, 완료 상태, 선택한 필터, 마지막 카테고리가 유지된다.
- [ ] `<script>alert(1)</script>`를 입력해도 실행되지 않고 글자 그대로 보인다.
- [ ] 서버 없이 `index.html`을 더블클릭해 열어도 모든 기능이 동작한다.
- [ ] 360px 폭에서 가로 스크롤 없이 쓸 수 있고, 키보드만으로 모든 기능을 쓸 수 있다.
- [ ] `node --test tests/`가 모두 통과한다.

# 2부. 설계 스펙

## 7. 파일 구성과 모듈 역할

```
index.html                 화면 뼈대. style.css → todo-core.js → app.js 순서로 불러옴
style.css                  스타일
todo-core.js               순수 로직 (화면·저장소에 의존하지 않음)
app.js                     화면 그리기, 이벤트 처리, localStorage 저장
tests/todo-core.test.js    node --test로 실행하는 로직 테스트
```

### 7.1 왜 이렇게 나누는가
`file://`로 열면 브라우저가 자바스크립트 모듈(`import`/`export`)을 막는다. 그래서 일반 `<script>` 태그로 파일을 불러온다. 로직(`todo-core.js`)과 화면 처리(`app.js`)를 나누면 로직을 브라우저 없이 Node 내장 테스트 도구로 검증할 수 있다.

### 7.2 `todo-core.js`
상태를 받아 **새 상태를 돌려주는** 순수 함수만 둔다. 받은 상태는 직접 바꾸지 않는다. 현재 시각과 ID는 호출하는 쪽에서 넘겨받아, 테스트 결과가 항상 같게 나오게 한다.

| 함수 | 역할 |
|---|---|
| `createState()` | 빈 초기 상태를 만든다 |
| `addTodo(state, { id, text, category, now })` | 할 일을 추가하고 `lastCategory`를 갱신한다. 내용이 비면 상태를 그대로 돌려준다 |
| `updateTodoText(state, id, text)` | 내용을 바꾼다. 비어 있으면 그대로 돌려준다 |
| `toggleTodo(state, id)` | 완료 여부를 뒤집는다 |
| `deleteTodo(state, id)` | 할 일을 삭제한다 |
| `clearCompleted(state)` | 완료 항목을 모두 삭제한다 |
| `setFilter(state, filter)` | 필터를 바꾼다. 허용되지 않은 값이면 그대로 돌려준다 |
| `getVisibleTodos(state)` | 필터를 적용하고 정렬한 목록을 돌려준다 |
| `getProgress(todos)` | `{ all, work, personal, study }`를 돌려준다. 각 값은 `{ done, total, percent }` |
| `parseSaved(json)` | 저장된 문자열을 검사해 `{ state, status }`를 돌려준다. `status`는 `ok`, `empty`, `corrupt` 중 하나 |

없는 ID로 수정·체크·삭제를 요청하면 상태를 바꾸지 않고 그대로 돌려준다.

**내보내기 방식**: 파일 끝에서 브라우저에서는 `window.TodoCore`로, Node에서는 `module.exports`로 같은 함수 묶음을 내보낸다. 같은 파일 하나를 브라우저와 테스트가 함께 쓴다.

```js
if (typeof module !== "undefined" && module.exports) {
  module.exports = TodoCore;
} else {
  window.TodoCore = TodoCore;
}
```

### 7.3 `app.js`
- 시작할 때 localStorage에서 읽어 `TodoCore.parseSaved()`로 상태를 만든다.
- 상태를 바꾸는 흐름은 하나뿐이다: **이벤트 → `TodoCore` 함수로 새 상태 생성 → `save()` → `render()`**.
- `render()`는 진행률, 필터 버튼, 목록, 빈 화면 안내, "완료 항목 지우기" 버튼을 모두 다시 그린다. 할 일 100개 이하에서는 전체를 다시 그려도 충분히 빠르다.
- 목록 이벤트는 목록 컨테이너 하나에 걸고(이벤트 위임), 각 항목의 `data-id`로 대상을 찾는다.
- ID는 `crypto.randomUUID()`로 만들고, 지원하지 않는 브라우저에서는 `Date.now()`와 난수를 조합한다.

## 8. 데이터 모델과 저장

### 8.1 저장 형식
localStorage의 `todo-app:v1` 키 하나에 JSON으로 저장한다.

```json
{
  "version": 1,
  "todos": [
    {
      "id": "k3f9x2",
      "text": "주간 보고서 작성",
      "category": "work",
      "completed": false,
      "createdAt": 1759395600000
    }
  ],
  "settings": { "filter": "all", "lastCategory": "work" }
}
```

| 필드 | 규칙 |
|---|---|
| `version` | 현재 `1`. 구조가 바뀔 때 변환 여부를 판단하는 데 쓴다 |
| `id` | 문자열. 고유값 |
| `text` | 앞뒤 공백을 제거한 1~200자 |
| `category` | `work`, `personal`, `study` 중 하나. 화면에는 업무/개인/공부로 표시 |
| `completed` | 완료 여부 (boolean) |
| `createdAt` | 추가한 시각 (밀리초 숫자). 정렬에 쓴다 |
| `settings.filter` | `all`, `work`, `personal`, `study` 중 하나 |
| `settings.lastCategory` | `work`, `personal`, `study` 중 하나. 할 일 추가 시 기본 카테고리 |

### 8.2 정렬 규칙
1. 미완료 항목이 위, 완료 항목이 아래다.
2. 각 그룹 안에서는 `createdAt`이 큰 것(최근 추가)이 위다.

완료를 체크해도 `createdAt`은 바뀌지 않으므로, 완료를 해제하면 원래 순서 자리로 돌아간다.

### 8.3 저장과 불러오기
- **저장**: 상태가 바뀔 때마다 즉시 전체를 저장한다. 할 일 20개 정도면 수 KB라 부담이 없다.
- **불러오기**: `parseSaved()`가 형식을 검사한다. 형식이 틀린 항목만 버리고 나머지는 살린다. 설정 값이 잘못됐으면 기본값(`filter: "all"`, `lastCategory: "work"`)을 쓴다.

## 9. 오류 처리

| 상황 | 처리 |
|---|---|
| 빈 입력, 공백만 입력 | 추가하지 않는다. 수정 중이었다면 원래 내용으로 돌아간다 |
| 200자 넘는 입력 | 입력창에 `maxlength="200"`을 두고, 로직에서도 200자로 자른다 |
| 저장된 데이터 없음 | 빈 목록으로 시작한다 (`status: "empty"`) |
| 저장된 JSON을 읽을 수 없음, 또는 `version`이 1이 아님 | 빈 목록으로 시작하고, 원본은 `todo-app:v1:corrupt` 키에 백업한 뒤 상단에 안내 문구를 띄운다 (`status: "corrupt"`) |
| 일부 항목만 형식이 틀림 | 그 항목만 버리고 나머지는 불러온다 |
| localStorage 읽기·쓰기 실패 (비공개 모드, 용량 초과) | 모든 접근을 `try/catch`로 감싼다. 앱은 계속 동작하고 "이 브라우저에서는 저장되지 않습니다" 안내를 띄운다 |
| 없는 ID로 수정·체크·삭제 | 상태를 바꾸지 않는다 |

## 11. 테스트

### 11.1 자동 테스트 (`node --test tests/`)
Node만 있으면 되고 따로 설치할 것이 없다. `todo-core.js`의 함수를 모두 검증한다.

- **추가**: 앞뒤 공백 제거, 빈 입력 거부, 200자 자르기, `lastCategory` 갱신, 원래 상태를 바꾸지 않음
- **수정·체크·삭제**: 정상 동작, 빈 내용으로 수정 시 유지, 없는 ID일 때 상태 유지
- **`clearCompleted`**: 미완료 항목만 남음
- **`setFilter`**: 허용된 값만 반영
- **`getVisibleTodos`**: 필터별 결과, 정렬 순서 (미완료 → 완료, 각 그룹 안에서 최신순), 완료 해제 시 원래 자리
- **`getProgress`**: 0개일 때 0%, 반올림 (7/12 → 58%), 카테고리별 집계
- **`parseSaved`**: 정상 데이터, 빈 값, 손상된 JSON, 형식이 틀린 항목 섞임, 알 수 없는 버전, 잘못된 설정 값

### 11.2 브라우저 확인 (개발 시에만)
Playwright로 `file://` 경로의 `index.html`을 열어 핵심 흐름을 확인한다: 추가 → 체크 → 수정 → 삭제 → 완료 항목 지우기 → 새로고침 후 유지, `<script>` 입력이 실행되지 않음. 앱 실행에는 필요 없다.

### 11.3 직접 확인
360px 폭 화면과 키보드만으로 조작하는 경우를 6절 수용 기준으로 확인한다.
