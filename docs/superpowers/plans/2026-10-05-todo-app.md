# 할 일 관리 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 브라우저에서 바로 실행되는 개인용 할 일 관리 앱을 순수 JavaScript로 구현한다.

**Architecture:** `app.js` 한 파일을 저장, 상태, 순수 함수, 렌더, 이벤트 다섯 구역으로 나눈다. 정렬, 필터, 진행률 집계는 DOM을 참조하지 않는 순수 함수로 분리해 `tests.html`에서 검증한다. 상태가 바뀌면 localStorage에 저장하고 목록 영역을 전부 다시 그린다.

**Tech Stack:** HTML, CSS, JavaScript (ES2020). 외부 의존성과 빌드 도구 없음.

**Spec:** [docs/superpowers/specs/2026-10-05-todo-app-design.md](../specs/2026-10-05-todo-app-design.md)

## Global Constraints

모든 과제의 요구사항에 아래가 암묵적으로 포함된다. 값은 PRD에서 그대로 가져왔다.

- 외부 라이브러리, 패키지 매니저, 빌드 도구를 쓰지 않는다. `package.json`을 만들지 않는다.
- `<script type="module">`과 `import` / `export`를 쓰지 않는다. `file://`에서 CORS로 막힌다. `app.js`는 일반 스크립트 한 개다.
- `crypto.randomUUID()`를 쓰지 않는다. 보안 컨텍스트를 요구해서 `file://`에서 브라우저별로 동작이 갈린다.
- localStorage 키는 `todos.v1`, 손상 데이터 보관 키는 `todos.v1.broken`.
- 카테고리는 `"업무"`, `"개인"`, `"공부"` 세 개로 고정한다. 추가나 편집 기능을 만들지 않는다.
- 진행률은 **항상 전체 데이터 기준**으로 계산한다. 필터 상태를 반영하지 않는다.
- 필터 기본값은 카테고리 `"전체"`, 상태 `"전체"`.
- 삭제에 확인 대화상자를 두지 않는다.
- 사용자에게 보이는 문자열은 한국어로 쓴다. 완결된 문장은 마침표로 끝내고, 버튼 라벨과 제목에는 마침표를 붙이지 않는다.
- 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>` 를 넣는다.

## Review Focus

PRD가 전제하지만 어느 과제의 테스트도 직접 다루지 않는 입력들이다. 각 줄마다 담당 과제에 테스트를 추가해 두었다.

1. **할 일 텍스트에 HTML 특수문자가 들어간 경우** (`<img src=x onerror=alert(1)>`) — `innerHTML`로 그리면 마크업으로 해석된다. 사용자 텍스트는 `textContent`로만 넣어야 한다. → Task 4
2. **`todos.v1`에 배열이 아닌 유효한 JSON이 들어 있는 경우** (`{}`, `"abc"`, `null`) — `JSON.parse`는 성공하므로 파싱 성공만 확인하면 통과해 버린다. 배열 여부를 따로 검사해야 한다. → Task 2
3. **같은 밀리초에 두 건을 추가한 경우** — id가 겹치면 완료 토글과 삭제가 엉뚱한 항목에 적용된다. → Task 1
4. **매우 긴 텍스트와 공백 없는 긴 문자열** — 레이아웃이 가로로 밀려 삭제 버튼이 화면 밖으로 나간다. → Task 3
5. **항목이 0개일 때의 진행률** — 분모가 0이면 `NaN%`가 표시된다. → Task 1

- [ ] **Step 2: 실패하는 테스트를 작성한다**

```js
// makeId
assertEqual(typeof makeId(), "string", "makeId는 문자열을 돌려준다");
const ids = new Set(Array.from({length: 1000}, makeId));
assertEqual(ids.size, 1000, "makeId는 연속 1000회 호출에도 중복되지 않는다");  // Review Focus 3

// sortTodos — 미완료가 완료보다 먼저
assertDeepEqual(
  sortTodos([t({id:"a", done:true}), t({id:"b", done:false})]).map(x => x.id),
  ["b", "a"], "미완료가 완료보다 앞에 온다");

// sortTodos — 마감일 빠른 순, 없는 항목은 뒤
assertDeepEqual(
  sortTodos([t({id:"a", dueDate:null}), t({id:"b", dueDate:"2026-10-09"}), t({id:"c", dueDate:"2026-10-07"})]).map(x => x.id),
  ["c", "b", "a"], "마감일이 빠른 순, 없는 항목은 뒤로 간다");

// sortTodos — 마감일이 같으면 나중에 추가한 것이 위
assertDeepEqual(
  sortTodos([t({id:"a", createdAt:100}), t({id:"b", createdAt:200})]).map(x => x.id),
  ["b", "a"], "마감일이 없으면 나중에 추가한 것이 위에 온다");

// sortTodos — 원본 불변
const src = [t({id:"a", done:true}), t({id:"b", done:false})];
sortTodos(src);
assertDeepEqual(src.map(x => x.id), ["a", "b"], "sortTodos는 원본 배열을 바꾸지 않는다");

// filterTodos — 두 축 AND
const sample = [
  t({id:"a", category:"업무", done:false}),
  t({id:"b", category:"업무", done:true}),
  t({id:"c", category:"개인", done:false}),
];
assertDeepEqual(filterTodos(sample, {category:"전체", status:"전체"}).map(x => x.id), ["a","b","c"], "전체/전체는 모두 통과한다");
assertDeepEqual(filterTodos(sample, {category:"업무", status:"미완료"}).map(x => x.id), ["a"], "카테고리와 상태는 AND로 적용된다");
assertDeepEqual(filterTodos(sample, {category:"전체", status:"완료"}).map(x => x.id), ["b"], "상태 완료는 완료 항목만 남긴다");
assertDeepEqual(filterTodos(sample, {category:"공부", status:"전체"}).map(x => x.id), [], "해당 카테고리가 없으면 빈 배열이다");

// calcProgress
assertDeepEqual(calcProgress(sample), {done:1, total:3, percent:33}, "진행률은 백분율을 정수로 내림한다");
assertDeepEqual(calcProgress([]), {done:0, total:0, percent:0}, "항목이 없으면 0/0, 0%다");  // Review Focus 5

// countByCategory
assertDeepEqual(countByCategory(sample, "업무"), {done:1, total:2}, "카테고리별 집계는 해당 카테고리만 센다");
```

`t(overrides)`는 테스트용 `Todo` 생성 헬퍼다. 기본값 `{id:"x", text:"할 일", category:"개인", done:false, dueDate:null, createdAt:0}`에 `overrides`를 덮어쓴다. `tests.html` 안에 둔다.

## Task 2: 저장 계층

**Files:**
- Modify: `app.js`
- Modify: `tests.html`

**Interfaces:**
- Consumes: Task 1의 함수 없음 (독립적이다)
- Produces:
  - `STORAGE_KEY = "todos.v1"` (상수)
  - `BROKEN_KEY = "todos.v1.broken"` (상수)
  - `loadTodos(key = STORAGE_KEY) -> Todo[]`
  - `saveTodos(todos: Todo[], key = STORAGE_KEY) -> void`

**키를 인자로 받는 이유:** 테스트가 실제 사용자 데이터(`todos.v1`)를 건드리지 않고 별도 키로 검증할 수 있어야 한다. 앱 코드는 인자 없이 호출한다.

- [ ] **Step 1: 실패하는 테스트를 작성한다**

```js
const K = "todos.test";
const KB = K + ".broken";

// 왕복
localStorage.removeItem(K);
saveTodos([t({id:"a"})], K);
assertDeepEqual(loadTodos(K).map(x => x.id), ["a"], "저장한 내용을 그대로 읽어온다");

// 키가 없으면 빈 배열
localStorage.removeItem(K);
assertDeepEqual(loadTodos(K), [], "저장된 데이터가 없으면 빈 배열을 돌려준다");

// 파싱 실패 → 빈 배열 + 손상값 보관
localStorage.setItem(K, "{{{");
localStorage.removeItem(KB);
assertDeepEqual(loadTodos(K), [], "JSON이 깨졌으면 빈 배열로 시작한다");
assertEqual(localStorage.getItem(KB), "{{{", "깨진 값은 broken 키로 옮겨 보관한다");
assertEqual(localStorage.getItem(K), null, "깨진 값은 원래 키에서 제거한다");

// 배열이 아닌 유효 JSON → 같은 처리  (Review Focus 2)
for (const bad of ["{}", '"abc"', "null", "42"]) {
  localStorage.setItem(K, bad);
  localStorage.removeItem(KB);
  assertDeepEqual(loadTodos(K), [], `배열이 아닌 ${bad} 는 빈 배열로 처리한다`);
  assertEqual(localStorage.getItem(KB), bad, `배열이 아닌 ${bad} 도 broken 키로 옮긴다`);
}
```

// renderItem은 <li> 요소를 돌려주는 순수한 DOM 생성 함수다
const el = renderItem(t({text: '<img src=x onerror="window.__xss=1">'}));
assertEqual(el.querySelector(".todo-text").textContent, '<img src=x onerror="window.__xss=1">',
  "특수문자가 포함된 텍스트를 그대로 표시한다");
assertEqual(el.querySelector(".todo-text").querySelector("img"), null,
  "사용자 텍스트를 마크업으로 해석하지 않는다");
assertEqual(window.__xss, undefined, "렌더 과정에서 사용자 텍스트의 스크립트가 실행되지 않는다");
```

이 테스트를 위해 항목 하나를 만드는 부분을 `renderItem(todo) -> HTMLLIElement` 로 분리한다. `render()`가 이 함수를 호출한다.

- [ ] **Step 4: `renderItem` 과 `render` 를 구현한다**

`renderItem`은 Task 3 Step 1에 고정한 `<li>` 구조를 만든다. 텍스트, 카테고리, 마감일은 모두 `textContent`로 넣는다. `innerHTML`을 사용자 데이터에 쓰지 않는다. 마감일은 `MM/DD` 형태로 줄여 표시하고, `null`이면 해당 `<span>`을 비운다.

`render()`는 이 순서로 동작한다.

1. `#todo-list`를 비우고, `sortTodos(filterTodos(state.todos, state.filter))` 결과를 `renderItem`으로 그려 넣는다
2. `calcProgress(state.todos)`로 `#progress-fill`의 width, `#progress-count`, `#progress-percent`를 갱신한다 — **인자는 필터를 거치지 않은 `state.todos` 다**
3. `#category-tabs`의 각 버튼에 `countByCategory(state.todos, 카테고리)` 결과를 `n/m` 형태로 표시한다. `전체` 탭은 전체 개수만 표시한다
4. 1번 결과가 0건이면 `#empty-state`를 보이고, 전체가 0건일 때와 필터 때문에 0건일 때의 문구를 구분한다 (PRD 4.6절)

- [ ] **Step 6: `addTodo`, `toggleTodo`, `deleteTodo` 와 이벤트 연결을 구현한다**

`addTodo`는 `text.trim()`이 빈 문자열이면 아무것도 하지 않는다. 그 외에는 `makeId()`로 id를 만들고 `createdAt`에 `Date.now()`를 넣어 `state.todos`에 추가한다.

`#todo-form`의 `submit` 이벤트에 연결한다. `event.preventDefault()`를 호출한다. 추가 후 `#todo-input`을 비우고 포커스를 유지하며, `#due-input`을 비우고 `#category-select`는 그대로 둔다 (PRD 4.1절).

`toggleTodo`와 `deleteTodo`는 `#todo-list`에 이벤트 위임으로 연결한다. `event.target`의 클래스(`todo-check` / `todo-delete`)로 분기하고, 가장 가까운 `.todo-item`의 `data-id`를 읽는다. 항목이 매번 다시 그려지므로 개별 요소에 리스너를 붙이지 않는다.

마지막에 `state.todos = loadTodos()`로 초기화하고 `render()`를 한 번 호출한다. 이 부트스트랩은 `app.js` 최하단에 두고 조건 없이 실행한다 — `tests.html`이 Task 1에서 넣어 둔 스텁 마크업을 가지고 있으므로 테스트 페이지에서도 예외 없이 동작한다.

**Interfaces:**

- [ ] **Step 3: `updateTodoText` 를 구현한다**

`text.trim()`이 빈 문자열이면 상태를 바꾸지 않고 종료한다. 그 외에는 해당 id의 `text`를 `trim()` 결과로 바꾸고, 저장 후 `render()`를 호출한다.

```

- [ ] **Step 5: `startEdit` 과 인라인 편집 UI를 구현한다**

`.todo-text` 클릭 시 해당 `<span>`을 `<input type="text">`로 교체하고 현재 텍스트를 담아 포커스를 준다.

편집 종료 경로는 PRD 4.3절의 세 가지다.

| 이벤트 | 처리 |
|---|---|
| `keydown` Enter | `updateTodoText(id, input.value)` 호출 |
| `keydown` Escape | 편집 상태를 **먼저** 해제한 뒤 `render()`로 원래 텍스트를 복원한다 |
| `blur` | `updateTodoText(id, input.value)` 호출 |

Escape가 편집 상태를 먼저 해제해야 한다. 그러지 않으면 뒤따라 발생하는 `blur`가 저장으로 처리된다. 편집 중인 id를 담는 변수 하나를 두고, `blur` 핸들러에서 그 변수가 비어 있으면 아무것도 하지 않는 방식으로 구현한다.

- [ ] **Step 6: `setFilter` 와 필터 버튼을 연결한다**

`setFilter`는 `state.filter`에 전달받은 값을 병합하고 `render()`를 호출한다. **`saveTodos`를 호출하지 않는다** — 필터는 데이터가 아니고 저장하지 않는다 (PRD 4.5절).

`#category-tabs`와 `#status-filter`에 이벤트 위임으로 연결한다. 버튼의 `data-category` 또는 `data-status` 값을 읽어 `setFilter`에 넘긴다. `render()`가 현재 `state.filter`와 일치하는 버튼에 `is-active` 클래스를 붙이도록 Task 4의 `render()`에 한 단계를 추가한다.
